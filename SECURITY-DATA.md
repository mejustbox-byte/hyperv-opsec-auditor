# Защита evidence и отчетов

## Классификация и минимизация

JSON может раскрывать изоляцию, наличие резервного копирования, состояние администраторов и пробелы контроля; итоговый отчет наследует эту чувствительность. Сборщик отсутствует: владелец вручную экспортирует разрешенные сведения, проверяет происхождение и переносит через утвержденный канал. Используйте псевдонимы, без секретов, реальных адресов, SID/ACL и полной топологии. Псевдонимизация не делает данные автоматически анонимными. Схема не является детектором секретов в разрешенных строках.

Граница доверия: исходная инфраструктура → ручной экспорт → локальный JSON → валидатор/правила → отчет → решение владельца. Приложение доверяет предоставленным фактам после проверки **структуры**, а не их истинности. Факт восстановления должен опираться на протокол отдельного стенда; успешный parse не подтверждает restore.

## Хранение и доступ

Размещайте реальные файлы вне checkout и синхронизируемых публичных каталогов. На POSIX до запуска задайте `umask 077`, создайте личный каталог с режимом 0700; для Windows используйте каталог с проверенным ACL текущего оператора и необходимых администраторов. Шифрование диска и ключей, безопасный транспорт, права журналов терминала/CI и доступ к копиям обеспечивает владелец. CLI не меняет ACL и не предоставляет хранилище секретов. Library возвращает данные в памяти, поэтому вызывающий код отвечает за их сохранение.

Выбирайте JSON вывод только в разрешенный приватный файл; не отправляйте реальные данные в общедоступные Actions artifacts, Issues или PR. stdout может сохраняться оболочкой/CI. `--output` отказывает при существующем файле; используйте новый путь вместо попыток перезаписи. Ошибки входа не должны отображать его значения; не заменяйте безопасное сообщение дампом.

## Retention и инциденты

Автоматической retention/очистки нет. До аудита владелец письменно определяет цель, ответственного, срок, доступ и способ удаления; ограничивайте срок минимально необходимым. Например, короткий срок для рабочего экспорта и отдельный утвержденный срок для протокола приемки, без универсального навязанного числа дней. Ведите реестр файлов/копий, проверяйте истечение, удаляйте экспорт, отчеты, журналы терминала и копии по политике организации. Обычное удаление файла не гарантирует стирание SSD, снапшотов или резервных копий; учитывайте криптографическое стирание/политику носителей.

При утечке ограничьте доступ, сохраните минимальные приватные сведения для расследования, оцените раскрытые границы управления и смените затронутые настоящие секреты средствами организации. Удаление файла из Git не стирает историю, forks и Actions artifacts; согласуйте очищение и уведомление с владельцем. Не вставляйте содержимое в публичное сообщение об инциденте.

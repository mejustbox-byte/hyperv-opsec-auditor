# Облачная разработка и восстановление среды

## Что предоставляет среда

Linux, рабочая копия `/workspace/hyperv-opsec-auditor`, Python 3.12+, Git и разрешенное платформенное подключение GitHub. Нет Hyper-V роли, приватного Windows стенда, фоновых сервисов, платных ресурсов или производственных секретов. Отсутствие проектных секретов не означает отсутствие платформенной аутентификации; ее значения не читаются и не выводятся.

## Установка без сохраненной venv

```bash
cd /workspace/hyperv-opsec-auditor
git status --short --branch
bash tools/setup_env.sh
.venv/bin/python -m coverage run --source=hyperv_opsec_auditor -m unittest discover -s tests -v
.venv/bin/python -m coverage report --fail-under=85
.venv/bin/python tools/validate_docs.py
.venv/bin/python tools/scan_secrets.py
.venv/bin/python tools/build_release.py
.venv/bin/python tools/package_smoke.py
```

Используйте существующую копию без нового рабочего дерева Git, если его явно не запросили. Установка сохраняет исходники и lock; проверяет TLS/хеши. Python 3.12.14 проверен в текущей машине. Описания полей настройки `install_script` и `start_skill` — на русском. Установка без прежней venv и повторный запуск проверены в текущем цикле. Русские install_script/start_skill сохранены в draft; это не публикация снимка.

## Сеть и учетные данные

PyPI нужен только для разработки/сборки; wheel устанавливается без индекса. Git/API и загрузка файлов имеют отдельные маршруты и права. В настройках сохранены необходимые домены GitHub без секретных значений. 401 не обходится извлечением токена; для публикации используется workflow с токеном GitHub Actions. Разрешение HTTP домена не гарантирует успешной авторизации.

## Черновик, публикация, новая задача

Сохранение draft только сохраняет инструкции; не выполняет их и не публикует снимок. Пользователь проверяет и сохраняет настройки, затем публикует среду через интерфейс продукта. После публикации в новой задаче проверить рабочую копию, версию, установку и синтетический аудит, не предполагая сохранения процессов или аутентификации. В этом цикле свежая задача после публикации облачного снимка **НЕ ПРОВЕРЕНА**; чистая локальная venv — другое доказательство.

При восстановлении сначала проверить состояние и сохранить чужие изменения; не сбрасывать рабочую копию и не удалять неизвестную среду. При отсутствии venv выполнить установку выше. Если GitHub недоступен, автономные тесты остаются доступными; отдельно зафиксировать блокер публикации. Публикация GitHub Release не публикует облачную среду.

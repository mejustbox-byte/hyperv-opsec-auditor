# Правила участия в разработке

Вся документация, пояснения правил и схем, пользовательская справка, шаблоны сообщений и примеры отчетов пишутся на русском языке. Имена команд, пути, ключи JSON, идентификаторы, названия технологий и код сохраняются. Не переводите `pass`, `fail`, `unknown`, `not_run` и другие значения машинного контракта.

Используйте существующую рабочую копию; отдельное рабочее дерево Git создавайте только по явному запросу. Изменения оформляйте отдельной веткой и PR. Опишите поведение, причины, проведенные проверки и ограничения. Не меняйте существующие теги и не удаляйте старые выпуски ради перевода.

## Воспроизводимые проверки

```bash
bash tools/setup_env.sh
.venv/bin/python -m coverage run --source=hyperv_opsec_auditor -m unittest discover -s tests -v
.venv/bin/python -m coverage report --fail-under=85
.venv/bin/python tools/validate_docs.py
.venv/bin/python tools/scan_secrets.py
.venv/bin/python tools/build_release.py
.venv/bin/python tools/package_smoke.py
```

Добавляйте содержательные тесты новых правил, неполных и некорректных данных. Для проверки русского текста сохраняйте файлы в UTF-8. Не добавляйте реальные секреты, учетные данные, производственные сведения и отчеты. Проверка известных шаблонов секретов не гарантирует отсутствия любых утечек.

Синтетические тесты на Linux и предоставленных GitHub исполнителях Windows не заменяют испытания Windows Server Hyper-V/HGS, сетевой изоляции и восстановления. Такие испытания выполняются только на отдельном поддерживаемом стенде по `docs/lab.md`; невыполненные проверки явно указываются в PR и описании выпуска. Платные ресурсы без отдельного разрешения не создаются.

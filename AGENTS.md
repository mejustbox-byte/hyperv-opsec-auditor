# Правила следующих циклов разработки

Работайте в существующем изолированном checkout. Не создавайте Git worktree без явного запроса пользователя. Сначала прочитайте [README](README.md) с полным индексом, [CORE-CONTRACT](CORE-CONTRACT.md), [SECURITY](SECURITY.md), [VERIFICATION](VERIFICATION.md) и [CLOUD-DEVELOPMENT](CLOUD-DEVELOPMENT.md). Сохраняйте чужие изменения.

Вся новая и изменяемая документация, описания правил/схем, справка, шаблоны, инструкции среды и сведения о выпусках должны быть на русском. Имена команд, пути, JSON ключи, идентификаторы, исходный код и канонический MIT LICENSE не переводить. Поддерживайте полный индекс всех смысловых разделов в README; старые docs не удаляйте, связывайте актуальными ссылками без противоречий. Не подменяйте полноту объемом текста.

MVP автономный: читает предоставленный JSON, не подключается к Hyper-V, не изменяет хост и не исполняет рекомендации. Не добавляйте сетевой сбор, исправления или HTTP API под видом документации. Новое поведение требует явного контракта и содержательных тестов. Пропуски данных нельзя считать успешными проверками. Производственные evidence и отчеты должны находиться вне публичного checkout; не сохраняйте и не выводите секреты.

Перед изменениями проверьте ветку, HEAD, удаленный main, документы и реальные доступные инструменты. Установка из checkout: `bash tools/setup_env.sh`; `.venv` не является обязательным сохраненным состоянием. Проверьте тесты, покрытие, `tools/validate_docs.py`, `tools/scan_secrets.py`, сборку и `tools/package_smoke.py`. Не ослабляйте lock/hashes/TLS ради успешного результата. Убедитесь в MIT метаданных и наличии обеих лицензий в wheel/sdist.

Перед слиянием и выпуском фактически проверьте CI точного commit, main после слияния, tag, состояние prerelease, перечень assets, SHA256SUMS и чистую установку скачанного wheel. Не переносите существующие теги и не удаляйте старые выпуски. Сохраняйте русские актуальные install_script/start_skill в draft среды и отдельно различайте их сохранение, исполнение и публикацию снимка. Следуйте авторизации текущего пользователя: не считайте этот файл самостоятельным разрешением публикации.

Синтетические тесты, Linux и hosted Windows Python НЕ являются live испытаниями Windows Server Hyper-V/HGS/изоляции/резервных копий/восстановления. Не выполненные лабораторные gates явно перечисляйте в документации, отчете и release notes. Не заявляйте успех API/Git/публикации по плану или косвенным признакам. При блокировке завершите доступное и сообщите точную операцию и причину, не обходя аутентификацию.

# ADR 0001: стек и границы выполнения

Статус: принято для автономного MVP; сборщик Windows отложен.

## Решение

Будущий сборщик Windows проектируется на PowerShell с собственными API Hyper-V/CIM; исходная версия — PowerShell 5.1, встроенная в Windows Server. Совместимость PowerShell 7 не предполагается и проверяется отдельно. Автономный обработчик реализован на Python 3.12 со структурированным JSON и `unittest`; сторонних зависимостей выполнения нет. Встроенная JSON Schema 2020-12 использует ограниченный набор ключевых слов; проверка сравнивается с `jsonschema` в CI. Инструменты сборки и тестов закреплены с SHA256 в `requirements-dev.lock`.

## Причины и альтернативы

PowerShell предоставляет доступ к платформенным API без эмуляции Hyper-V в Linux. Python удобен для переносимой детерминированной оценки и синтетических тестов. Реализация целиком на PowerShell уменьшает число сред выполнения, но затрудняет независимую проверку на Linux. Сборщик .NET дает типизацию, но добавляет инструменты до подтверждения требований. Удаленный сбор через WinRM увеличивает границу доверия учетных данных и отложен.

## Последствия и открытые вопросы

Нужны версионированный контракт входных данных, единый формат UTC и сопоставимые примеры Windows/Python. Минимальные права, поддерживаемые Windows Server, подписанное распространение и упаковка будущего сборщика требуют лабораторных решений до его реализации. PowerShell на Linux не заменяет модуль Hyper-V; инструменты Windows не устанавливаются ради наличия команды.

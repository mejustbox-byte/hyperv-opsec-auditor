# Модель угроз

## Активы и границы доверия
Активы: host OS, management plane, административные идентичности, VM/гостевые данные, vSwitch/VLAN, VHDX/checkpoints, key protectors/HGS, backup и журналы. Границы: рабочая станция администратора → WinRM/host; host → VM; VM → virtual network; host → storage/backup; host → HGS; collector → offline evaluator → report consumer.

## Противники и сценарии
| Сценарий | Последствие | Evidence / контроль | Ограничение |
|---|---|---|---|
| Компрометация администратора или WinRM | Управление всеми VM | Группы, делегирование, auth/TLS, firewall, PAW policy | Без внешнего evidence MFA/PAW неизвестны |
| VM пересекает сетевую границу | Латеральное перемещение | Switch/VLAN/trunk/SR-IOV и утвержденная топология | Конфигурация не доказывает runtime фильтрацию |
| Подмена загрузки/кража диска VM | Раскрытие данных | Gen2 Secure Boot, vTPM, shielding/key protection | Host compromise ограничивает доверие к выводам |
| Ransomware получает storage/backup права | Потеря VM и восстановления | ACL, отдельные identity, immutable/offline copy, restore drill | Checkpoint и наличие backup не доказывают restore |
| Удаление журналов или подмена evidence | Ложный pass | Retention, внешний сбор, provenance и freshness | Захваченный host может лгать collector |
| Утечка отчета или фикстуры | Раскрытие инфраструктуры | Redaction, минимизация, access control | Отчеты считаются чувствительными |
| Вредоносные входные данные | Ошибка evaluator/инъекция | Схема, лимиты, отсутствие eval/команд из данных | Тесты ограничены синтетическими входами |

## Предположения и остаточный риск
Владелец разрешает аудит; известна ожидаемая топология и политика; лаборатория изолирована. Read-only API не гарантирует отсутствия побочных событий: сбор может создавать audit events и нагрузку. Нельзя гарантировать целостность данных от компрометированного хоста. Аудитор не является penetration test, защитой от ransomware или сертификатом соответствия. Отказ доступа не обходится и фиксируется как unknown.

## Защита offline MVP
Вход — недоверенный локальный JSON до 2 MiB: запрещены duplicate keys, unknown fields, non-finite numbers, неправильные типы/даты и повторные inventory IDs. Нет сетевых вызовов, eval, subprocess или извлечения архивов в evaluator. IDs допускают только короткие псевдонимы. Markdown значения экранируются, ошибки не печатают входные значения. Выходные файлы создаются исключительно и не перезаписываются, включая symlinks; stdout требует защищенного места хранения.

Остаточный риск: владелец может подать ложные approved/expected поля. JSON схема подтверждает структуру, а не истинность evidence; collected_at и drill timestamps не являются криптографически проверенными. Весь JSON отчет остается чувствительным, даже с псевдонимами. Отчеты не включают полный исходный документ.

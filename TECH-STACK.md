# Стек, версии и обоснование

## Выполнение продукта

Пакет `hyperv-opsec-auditor 0.1.0a2`, Python >=3.12; текущая облачная проверка выполнена на Python 3.12.14. CI закрепляет ветку Python 3.12 на Ubuntu 24.04 и Windows Server 2022. Точная исправленная версия Python в CI определяется журналом запуска; 3.12.14 не приписывается всем исполнителям автоматически. Зависимостей выполнения в `pyproject.toml` нет: используются стандартные `argparse`, `json`, `datetime`, `pathlib`, `html`, `importlib.resources`.

JSON Schema 2020-12 с контрактом данных 1.0 включена в wheel. Встроенный проверяющий поддерживает только ее используемые ключевые слова. Совпадение со сторонним `jsonschema` проверяется в тестах, но тот не требуется пользователю wheel.

`requirements-dev.txt` задает версии; `requirements-dev.lock` содержит SHA256 доступных wheel. Установка использует `--require-hashes --only-binary=:all:`. TLS и проверка хешей не отключаются. Хеши не являются подписью издателя. Actions закреплены полными SHA в `.github/workflows/`; идентификаторы не переводятся.

## Почему этот стек

Python обеспечивает переносимую детерминированную автономную оценку без платформенных зависимостей Hyper-V. `unittest` не требует дополнительного тестового сервера. Windows-сборщик пока не реализован; предполагаемый PowerShell 5.1 и ограничения совместимости PowerShell 7 описаны в [ADR](docs/adr/0001-stack.md). Ни PowerShell на Linux, ни исполнители CI Windows не заменяют поддерживаемый стенд Hyper-V.

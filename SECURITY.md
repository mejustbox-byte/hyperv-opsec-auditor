# Политика безопасности

## Поддержка и границы

Проект — автономный аудитор предоставленных JSON, только для чтения. Он не подключается к Hyper-V, не исправляет настройки, не подтверждает соответствие нормативам и не защищает от программ-вымогателей. Реальные платформенные испытания не выполнены. [Модель угроз](THREAT-MODEL.md) и [испытания](SECURITY-TESTING.md) обязательны перед использованием выводов.

| Выпуск | Статус | Обработка сообщений |
|---|---|---|
| 0.1.0a2 | Текущий предварительный выпуск после публикации | Сообщения рассматриваются для актуального main; стабильность и сроки исправлений не гарантируются |
| 0.1.0a1 | Исторический предварительный выпуск | Сохраняется для воспроизводимости; отдельные обратные переносы исправлений не обещаются; обновляйтесь до актуального prerelease |
| Неопубликованные изменения | Разработка | Только воспроизводимые сообщения относительно точного commit |

Нет стабильного поддерживаемого выпуска и соглашения о сроках ответа. Изменения схемы в будущем предварительном выпуске могут потребовать ручной миграции; следите за CHANGELOG.

## Сообщение об уязвимости

Проверьте вкладку [Security репозитория](https://github.com/mejustbox-byte/hyperv-opsec-auditor/security). Если GitHub предоставляет кнопку приватного сообщения, используйте ее. Наличие этой функции или иного приватного канала здесь не обещается. Если кнопки нет, создайте публичную задачу с просьбой согласовать приватный канал, без деталей эксплуатации, настоящих данных или секретов. Дождитесь согласованного канала до отправки чувствительных подробностей; не используйте выдуманный адрес электронной почты.

Безопасное сообщение включает версию/commit, ОС/Python, затронутый CLI/library контракт, ожидаемое и фактическое поведение, минимальный **синтетический** пример, влияние и возможное ограничение. Не прикладывайте рабочие IP, учетные данные, токены, реальные SID/ACL/топологию, VHDX или резервные копии. Не проверяйте эксплуатацию на чужой инфраструктуре. Владелец рассматривает воспроизводимость и изменение риска; согласование раскрытия выполняется отдельно, без обещания SLA.

## Защита данных и доверие

Входные данные недоверенные; строгая схема, ограничения размера/строк/коллекций, отказ дублирующим ключам и нечисловым JSON константам снижают риск обработки. Вывод экранируется, неизвестные поля отвергаются, отчеты по CLI создаются без перезаписи существующих файлов; причины ошибок не выводят значение поврежденных данных. Компрометированный источник способен лгать: подписей и независимой аттестации нет. Локальный пользователь и Python находятся внутри границы доверия; гонки локальной ФС и компрометация процесса полностью не устраняются.

Evidence и отчеты классифицируются как конфиденциальные, даже без учетных данных. CLI не задает автоматическое шифрование, удаление или срок хранения. Владелец выполняет [политику хранения](SECURITY-DATA.md), проверяет права каталогов, независимые резервные копии и удаление по своей политике. В публичных fixtures допустимы только вымышленные данные.

## Поставка и проверка

[SUPPLY-CHAIN](SUPPLY-CHAIN.md) перечисляет точные версии, лицензии, контроль установки и выпуска. Код проекта MIT; LICENSE и русский перевод включаются в wheel/sdist. Контрольные суммы выявляют изменение загрузки, но сами по себе не подтверждают доверие издателю. Подписи издателя/SBOM-аттестация не реализованы. Проверяйте официальный репозиторий, тег, commit и успешный release workflow.

[SECURITY-TESTING](SECURITY-TESTING.md) отличает выполненные автономные проверки от НЕ ВЫПОЛНЕННЫХ лабораторных gates. Успешные Linux/hosted Windows тесты не удостоверяют WinRM, HGS, эффективные права или восстановление. Основные остаточные риски: ложный evidence, недостаточная полнота, устаревшие данные, неверная применимость платформы, компрометация администраторов и цепочки поставки.

# Локальный ПК и отдельная лаборатория Windows Server

## Ответственность и поддержка

Облачный Linux выполняет только разработку и синтетические тесты. Реальный стенд предоставляет владелец: Windows Server с ролью Hyper-V, поддерживаемая аппаратная либо вложенная виртуализация, подходящие CPU/SLAT/прошивка, версия/редакция/гости. Создание платных ресурсов не входит в настройку. Произвольная облачная VM не считается совместимой. HGS/Shielded VM требуют отдельной поддерживаемой инфраструктуры и доверия.

## Автономная проверка на ПК

Установите Python 3.12 и проверенный wheel по [INSTALL](INSTALL.md). Выполните `--version`, `validate` и `audit` вымышленного healthy.json с `--as-of 2026-10-09T00:00:00Z`. Ожидаются версия 0.1.0a2 и десять pass; это проверка установки, а не хоста. На Linux используются POSIX команды, на Windows — PowerShell команды документа установки. macOS отдельно не проверен.

## Реальные испытания — НЕ ВЫПОЛНЕНЫ

| Область | Необходимое доказательство владельца |
|---|---|
| Хост/управление | Поддержка сборки, обновления, эффективные группы/делегирование, отдельные учетные записи и сеть |
| WinRM | Реальные слушатели, HTTPS/сертификаты, аутентификация, правила межсетевого экрана и делегирование |
| VM/vSwitch/VLAN | Утвержденная топология и независимая проверка изоляции, транков/SR-IOV |
| Secure Boot/vTPM/Shielded VM | Поддерживаемые Gen1/Gen2/гостевые шаблоны, vTPM отдельно от shielding, ключи/HGS |
| Диски/контрольные точки/копии | Эффективные ACL/SMB/шифрование, отдельные права, независимая неизменяемая/автономная копия |
| Журналы | Политика аудита, внешняя доставка, сроки хранения и целостность |
| Восстановление | Изолированное упражнение без вредоносных программ, целостность, реальные RPO/RTO, утвержденный протокол |

Заранее зафиксируйте письменную область, профили, ожидаемые результаты, права, состояние и даты. Только тестовые данные, отсутствие маршрутов в производство. Нарушения создает владелец вне аудитора. Сборщик Windows не реализован: сведения предоставляются отдельно разрешенными средствами чтения и независимой проверкой. Аудитор потребляет их и не устанавливает истинность.

Протокол содержит сборку/оборудование/профиль, даты UTC, источники, ожидаемые и полученные результаты, ошибки/пропуски, состояние до/после, проверяющего и срок действия. Реальные экспорты не публикуются. Разрушительные упражнения требуют отдельного разрешения владельца. После испытаний владелец восстанавливает исходный стенд; продукт не выполняет очистку или восстановление. [Пошаговая лаборатория и Microsoft ссылки](docs/lab.md).
